# UX Profile

Generated by `setup-ui-ux-skills`. All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Custom: "case notebook"
- **Notes:** A detective's case notebook for a team game played on a shared Teams screen. Cool notebook paper `#F1F2F7`, white sheets `#FFFFFF`, fountain-pen indigo `#1D2051` for text and primary actions, highlighter yellow `#FFE34D` for found clues and the active player, stamp red `#C62A42` for destructive actions and private host areas, green `#0D6E4F` for solved and success. Type: Newsreader (serif) for stories, titles and clues; Schibsted Grotesk (sans) for interface text. Maximum 3 weights (400/600, plus the serif's 600). One main "sheet" surface per view (24px radius, 1px subtle border, soft shadow under 0.08 alpha); the scoreboard is a solid indigo panel. The memorable moment is the highlighter swipe when a clue is found; keep other motion quiet. 8px spacing grid (4px for micro gaps). Tokens live in `src/index.css` (`:root`).

## Banned anti-aesthetics

- Gratuitous glassmorphism / `backdrop-filter` without a high-contrast boundary
- Floating pastel pill badges for ordinary metadata (category, difficulty, IDs are plain text)
- Arbitrary decorative gradients and neon glowing borders
- Multi-color radial rainbow gradients on standard CTAs
- Cartoon empty-state illustrations (people waving / high-fiving)
- Nested scrollbars and icon bloat inside inputs

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** Normal text at least 4.5:1; large text, borders and UI components at least 3:1. Never use colour alone for meaning (pair it with text or an icon).
- **Touch / focus:** Minimum 44×44px tap targets (including small-looking buttons). Visible 3px indigo focus ring with 2px offset; never remove focus outlines. Respect `prefers-reduced-motion`.

## Brand tone and microcopy voice

- **Voice:** Opinionated & Direct
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Punchy and concise, with a light detective flavour where it helps ("Case closed", "Not found yet"), never at the cost of clarity. Buttons start with a verb and say exactly what happens (Mark solved +15, End game, Create link code); never OK, Submit or Continue. Errors say what happened and what to do next, without blaming the player. The interface text and the stories are in English.

## Icon library

- **Library:** Lucide
- **Package / path:** `lucide-react` (not installed yet; add it when the first icon is needed)
- **Notes:** Replace the current text symbols (↑ ↓ ✕ in the Story Editor, ✓ for "Solved") with Lucide icons when those areas are next touched. Stroke icons at 16–24px. One library only; no emoji as UI icons. Icon-only buttons are square, have an `aria-label` and a tooltip.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
6. Never use `window.confirm`, `window.alert` or `window.prompt`: some browsers (including the Claude app's built-in browser) block them. Use the in-page `ConfirmButton` dialog.
7. The Player View is shown on a shared Teams screen: it must never contain the solution before Reveal, unrevealed clues, or any keys.
